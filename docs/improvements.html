What emeans improves and adds to faiss e-means

emeans is a Rust port of faiss contrib/e_means. It keeps the same recipe and random stream (results within 0.43% of faiss), and improves and adds the parts below. Measured on an M1 Pro Mac and an RTX 3060 box.

Improved: how it works

Runs on the Mac GPU

faiss fails on Apple's GPU (MPS has no float64). emeans has its own Metal kernels.

0.74 s vs no run

Exact and fast on CUDA

A tensor-core screen picks candidate centroids, then an exact FP32 re-check. Proven bit-equal to plain FP32.

2× faiss FP32

Fast exact CPU on x86

A fused AVX2 kernel finds the best centroid inside the matrix multiply. No new dependency.

2× faiss torch CPU

Training stays on the GPU

Data, centroids and statistics stay on the device; the host joins only at revival checks and epoch ends.

1.20 → 0.16 s on CUDA

One tested contract

Every backend implements one op set, checked against an f64 reference, near-ties and a production-size case.

CPU = Metal = CUDA

BF16 only when asked

faiss defaults to BF16, which changes some labels. emeans stays exact unless you opt in.

exact by default

Added

Automatic k

Picks the number of clusters in two levels; re-splits clusters that are too big; stays flat when the data has no broad structure.

Near-duplicate groups

Bursts and retakes are grouped first (exact kNN, optional capture-time limit), so they do not distort the clusters.

~16k photos → ~2/3 as many groups

Robust outlier flag

Flags rows far below their cluster's typical similarity (median − 3 MAD), not a fixed 2% of every cluster.

Built-in embeddings

EmbeddingGemma 2 for images and text, exact against transformers; flash attention on CUDA.

2.6× faster bf16

Photos and videos

Fetches resized copies from Photos and iCloud, embeds video frames, and clusters photos and videos together.

Review before albums

A local gallery; albums are created in Photos only for the clusters you approve.

Added: incremental training with stable ids

Add new photos without starting over. Old cluster ids never change.

1 · AssignEach new item joins its nearest cluster; far-off items wait as pending.
2 · GrowA coherent group of ≥ 20 pending items becomes a new cluster.
3 · UpdateOne short e-means pass from the current state.
4 · RetrainOnly after large growth; ids carried over by matching.
